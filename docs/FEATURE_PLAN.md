# Shellium — SSH 终端软件功能规划与实现审计

> 基于 Qt 6.8+、libssh、libvterm 与 SQLite 的本地优先 SSH 终端和远程文件管理工具。

---

## 〇、审计结论

本文件同时承担功能规划和实现状态基线。状态来自 2026-08-08 对源码、数据库迁移、
CMake 测试目标及本机 macOS 构建结果的逐项核对。

状态记号：

- ✅ 已实现：存在可到达的产品入口、核心实现和相应自动化验证；
- ⚠️ 部分实现：主路径可用，但仍缺少表中明确列出的能力或平台验证；
- ❌ 未实现：没有产品入口或核心实现；
- ⏸ 待决策：必须先确定外部服务、协议、安全策略或产品范围，不能仅靠本地代码完成。

### 0.1 核心发布门槛

| 发布门槛 | 状态 | 已落地实现 |
|---|---|---|
| 当前服务器的远程文件管理 | ✅ | 每个 TerminalWorkspace 独占 RemoteFileManagerWidget；支持本地/远程双栏、路径直达、拖拽、递归上传下载、重命名、删除、断点续传、预览、chmod 与传输队列 |
| 自动识别当前进入的服务器层 | ✅ | Shell Integration 事件优先，SshSessionStack / SshSessionNode 自持会话层；命令解析仅作降级，绕过接管的层明确标记为“推测” |
| 文件管理自动跟随当前层 | ✅ | targetsChanged 后默认选择最内层；用户可关闭跟随并切回任意外层；内层 SFTP 经外层隧道路由，不从本机误直连同名内网地址 |
| 标签页隔离 | ✅ | 路径、目标层、SFTP 连接池请求、传输队列、暂停状态和会话凭据均不跨 TerminalWorkspace 共享 |

这一主线的实际数据流为：

~~~text
用户进入/退出内层 SSH
        ↓
Shell Integration 确认事件
        ↓（失败时才用命令解析降级）
TerminalPane 更新外层 → 内层目标链
        ↓
当前标签的 RemoteFileManagerWidget 自动选择最内层
        ↓
SftpService 使用独立连接，经正确的外层隧道访问该层
~~~

这比“读取终端标题或正则猜当前主机”的方案更可靠：已接管层的入栈、认证成功和通道 EOF
都是确定事件；推测路径不会被伪装成已确认层，高风险删除对话框也会明确展示目标服务器。

### 0.2 本轮已完成的原关键缺口

| 原缺口 | 当前状态 |
|---|---|
| 凭据保险库无人调用 | ✅ CredentialVault 已接入启动创建/解锁、主机凭据保存/读取、引用复用和 15 分钟闲置自动锁定 |
| 主机管理缺少 UI | ✅ 左侧主机树、嵌套分组、继承、搜索、标签筛选、最近连接、历史和安全导入导出已接通 |
| 端口转发无实现 | ✅ -L、-R、-D、规则 CRUD、一键启停、随连接启动、连接数与流量统计已接通 |
| 终端设置硬编码 | ✅ 跟随系统/亮/暗主题、字体、行高、字距、光标、滚动行数、铃声、自动重连和快捷键可配置 |
| 效率工具无实现 | ✅ Snippet 树、历史、历史补全、多主机执行已接通（广播输入页已移除，统一由工作区标题栏广播开关负责） |
| 工作区只有表结构 | ✅ 可保存、覆盖、打开、删除标签组合，并在替换前完整校验 JSON 和主机引用 |

### 0.3 当前剩余边界

目前仍不能称为“规划内全部功能完成”。剩余内容主要分为三类：

1. 发布加固：Linux CI、Windows 适配、真实多跳服务器回归、安装包签名/公证；
2. 可独立继续开发的增强：终端鼠标报告、终端感知块选区、标签拖出窗口、递归删除、
   URL 点击、会话日志、启动 Snippet、代理连接、系统钥匙串；
3. 必须先做产品/基础设施决策的 Phase 3：云同步、团队保险库、实时协作、SSO、AI 服务和
   插件市场。没有后端、身份体系、密钥恢复策略与供应商选择时，不应伪造“已完成”。

## 一、项目定位与技术基线

Shellium 面向需要在跳板机、内网多层服务器与 SFTP 之间频繁切换的桌面用户。项目坚持
本地优先：主机、历史、工作区和密文凭据默认保存在本机 SQLite，不依赖云服务。

### 1.1 目标平台

| 平台 | 优先级 | 当前验证 |
|---|---|---|
| macOS arm64 / x86_64 | P0 | ✅ arm64 Debug 构建和 7 个 CTest 目标通过 |
| Linux x86_64 | P0 | ⚠️ CMake 与 libutil 条件链接已准备，当前工作区没有 CI 实机结果 |
| Windows x86_64 | P1 | ❌ LocalShellWorker、socketpair 等 POSIX 路径仍需替换或条件实现 |

### 1.2 技术栈

| 层面 | 当前选型 |
|---|---|
| GUI | Qt Widgets 6.8+ |
| 语言 / 构建 | C++20、CMake 3.21+、Ninja |
| SSH / SFTP | libssh 0.11+ |
| 终端 | libvterm 0.3+ + Qt 文本文档渲染 |
| 本地终端 | POSIX PTY；Linux 额外链接 libutil |
| 存储 | SQLite + Qt SQL，事务与 WAL |
| 凭据加密 | libsodium Argon2id + XChaCha20-Poly1305 |
| 日志 | spdlog |

## 五、实际架构

### 5.1 核心类

| 类/模块 | 职责 |
|---|---|
| SshSessionStack | 一个终端的 SSH 层栈，在同一工作线程非阻塞泵送所有层 |
| SshSessionNode | 单层 libssh 会话、Shell、后台 exec、正向和远程转发状态机 |
| ShellShim | 安装远端 Shell Integration 并编码 OSC 事件 |
| SshCommandParser | Shell Integration 不可用时的保守推测路径 |
| TerminalPane | 合并已确认层与推测层，处理认证、重连、历史与终端回退 |
| TerminalWorkspace | 一个标签的 TerminalPane 与独占 RemoteFileManagerWidget |
| SshTunnelBroker | 把内层 SFTP/转发路由到正确外层 |
| SftpService | 独立线程与连接池中的同步 SFTP、递归传输和预览/chmod |
| CredentialVault / Vault | 保险库状态机、KDF、认证加密与凭据引用 |
| HostManagerWidget | 主机树、分组、搜索、最近连接和导入导出 |
| PortForwardRuntime | 独立网络线程中的 -L/-R/-D 生命周期与统计 |
| ProductivityModel/Widget | Snippet、历史、补全、多目标执行 |
| TerminalSettingsService | 设置加载、校验、原子保存、实时预览与广播 |
| ApplicationDatabase | SQLite schema、事务和全部领域记录 CRUD |

### 5.2 必须保留的架构约束

1. 第 N+1 层依赖第 N 层通道，建立和泵送必须非阻塞，不能在 SSH 工作线程等待自己；
2. 非阻塞 libssh channel 释放使用 free-only 路径，不先显式 close；
3. SFTP 使用独立连接和线程，不复用交互终端的 libssh 会话；
4. 已确认层与推测层严格隔离，命令解析不能弹出已确认层；
5. 所有高风险文件操作必须展示实际服务器，推测层必须带警示；
6. 凭据数据库只存密文，导入导出格式不得包含 password、passphrase、secret 或 credentialId；
7. 端口转发入站 fd 必须只有一个所有者，无法分发时立即关闭；
8. 新增网络、IO、并发和安全代码必须包含完整中文设计注释与失败路径说明。

详细原因见 ENGINEERING_NOTES.md。
